# intersvyaz-domofon-mqtt

MQTT-интерфейс для открывания домофона Интерсвязь (is74.ru).

MQTT здесь используется как **интерфейс команд**: клиент подписывается на топик, и при получении любого сообщения открывает дверь через REST-вызов. Это удобно для интеграции с Home Assistant, Node-RED и любой другой системой, умеющей публиковать в MQTT.

## Возможности

- Авторизация по SMS (телефон → код из SMS → выбор адреса, если их несколько).
- Токен сохраняется в файл и переиспользуется между запусками — повторный вход по SMS происходит только когда токен истёк.
- Если `relay_id` не указан в конфиге — при старте выводится список всех доступных реле, чтобы выбрать нужное.
- Данные всех камер, камер домофонов и доступные HLS URL публикуются в MQTT-топик `<base_topic>/cameras`.
- Автопереподключение к MQTT-брокеру при обрыве связи.

## Настройка

Скопируйте `config.example.yaml` в `config.yaml` и заполните:

```yaml
intersvyaz:
  phone: "+79001234567"      # телефон для входа по SMS
  relay_id: null             # оставьте null для первого запуска — см. ниже
  token_file: "intersvyaz_token.json"

mqtt:
  host: "192.168.1.10"
  port: 1883
  username: "mqtt_user"      # можно не указывать, если брокер без авторизации
  password: "mqtt_pass"
  base_topic: "intersvyaz/domofon"
```

### Определение relay_id

Если `relay_id` не задан, при первом запуске клиент авторизуется, выведет в
консоль/лог список всех реле вида:

```
RELAY_ID=12345  NAME=Подъезд 1
RELAY_ID=12346  NAME=Калитка
```

и завершит работу. Впишите нужный `RELAY_ID` в `config.yaml` и перезапустите.

## Запуск в Docker

Положите `config.yaml` в `./data/config.yaml`.

**Первый запуск — интерактивный**, нужно ввести код из SMS:

```bash
docker compose run --rm intersvyaz-domofon
```

Токен сохранится в `./data/intersvyaz_token.json` (том проброшен наружу,
переживёт пересоздание контейнера). После этого можно запускать в фоне:

```bash
docker compose up -d
```

Повторный ввод SMS-кода потребуется только если сохранённый токен истечёт —
тогда снова выполните

## MQTT-топики

Все топики формируются из `base_topic` (по умолчанию `intersvyaz/domofon`):

| Топик                          | Направление | Описание                                      |
|---------------------------------|-------------|------------------------------------------------|
| `<base_topic>/open/set`         | подписка    | любое сообщение сюда открывает дверь           |
| `<base_topic>/state`            | публикация  | `online` (retained) при подключении к брокеру  |
| `<base_topic>/result`           | публикация  | `OK` или `ERROR: ...` после попытки открытия   |
| `<base_topic>/relays`           | публикация  | JSON-список реле, если `relay_id` не задан     |
| `<base_topic>/cameras`           | публикация  | JSON-массив камер с UUID и URL `MEDIA.HLS.LIVE` |

В URL потока содержиться bearer-токен.

Пример открытия двери через `mosquitto_pub`:

```bash
mosquitto_pub -h 192.168.1.10 -t intersvyaz/domofon/open/set -m "open"
```

## Устранение неполадок

- **Токен постоянно истекает / просит SMS каждый раз** — проверьте, что том
  `./data` действительно примонтирован и файл `intersvyaz_token.json` в нём
  не пересоздаётся с нуля при каждом запуске контейнера.
- **`SystemExit(1)` сразу после старта** — это ожидаемое поведение, если
  `relay_id` не задан: смотрите вывод со списком реле в логах.
- **Не приходит SMS** — убедитесь, что номер в `phone` указан в том же
  формате, что и в приложении Интерсвязь (с `+7` или без — клиент сам убирает
  `+7` перед отправкой на сервер).
